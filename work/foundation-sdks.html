CASE 03 // PLATFORM ENGINEERING

Composable AI
foundations.

Extracting shared agent capabilities into independent SDKs so teams can compose what they need without maintaining divergent template forks.

The problem

Agent-builder templates shared capabilities such as PII redaction, guardrails, prompt management, tracing, and MCP integration. Those capabilities were duplicated inline. Improvements required manual changes across templates, while teams forked templates to swap components, causing copies to diverge.

The engineering task

Extract the shared functionality into reusable Foundation SDKs, keeping templates lean and allowing teams to compose the capabilities they needed without forking and maintaining their own variants.

Implementation approach

01 / Extract independent packages

I identified duplicated capabilities and separated them into individual Python packages. Because the templates were already in production, extraction required rewiring existing consumers, rebuilding regression suites, and adding edge cases around integration boundaries to preserve behavior.

02 / Support composition

Teams needed to swap providers—for example, one guardrail implementation for another—without rewriting the template. The SDK boundaries made those capabilities easier to select and reuse independently.

03 / Protect compatibility

Reusable packages can create dependency conflicts if their version ranges drift. I applied automated compatibility checks in CI to keep dependencies across SDKs within compatible ranges and reduce the risk of one package making another unusable.

Outcome

The redesign covered four templates, with SDK adoption across five to six teams. PII redaction became a default capability for nearly every team, and the pattern of maintaining divergent template forks largely stopped.

Reuse only works when the boundaries are real: independent packages, clear contracts, and compatibility checks.

What this demonstrates

  • Designing reusable developer-facing components.
  • Refactoring live integrations with regression protection.
  • Balancing flexibility with dependency compatibility.
  • Influencing adoption through better abstractions instead of mandates.

Disclosure: This case study describes the approach and outcomes at a high level. No internal source code or confidential platform details are included.
