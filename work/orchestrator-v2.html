CASE 01 // AI SYSTEMS ENGINEERING

Multi-agent orchestration:
outgrowing the framework.

A redesign of a TypeScript orchestration layer to support multiple model providers, standardize tool calling and structured outputs, and reduce latency without discarding the framework's useful state-management capabilities.

The problem

An orchestration service had been built on an older TypeScript graph framework. As adoption grew, teams needed multi-provider support, native tool calling, and structured outputs. Several capabilities available in the Python ecosystem were missing or unstable in the TypeScript version, and provider-specific parsing had begun to spread through workflow nodes.

Latency was also increasing. Independent steps were executed sequentially because the existing graph execution model did not provide the parallel behavior the workflow needed.

The design decision

Rather than replace the graph framework wholesale, I kept it for graph structure and state management, and redesigned the surrounding orchestration layer. This limited the scope of the rewrite while addressing the concrete constraints that were slowing teams down.

Implementation

01 / Put providers behind a common interface

I introduced a provider abstraction so graph nodes call a shared interface rather than a provider-specific API. Bedrock Converse, Azure OpenAI, and OpenAI implementations follow the same contract. This also made model routing possible: lightweight classification can use a smaller model, while more demanding reasoning can use a stronger one within the same workflow.

02 / Parallelize independent work

I restructured independent stages—such as guardrail pre-checks, context retrieval, and tool-call preparation—to fan out and merge. Promise.all handled parallel segments at the orchestration layer, while the graph framework continued to manage state for sequential parts of the workflow.

03 / Standardize tool calls and structured output

Provider-specific tool-call parsing was moved behind the adapter contract. This reduced custom parsing in individual nodes and gave teams a consistent way to work with tool calls and structured responses across providers.

Outcome

30%Latency reduction on the same workloads

< 1 weekTo add a third model provider

The redesign reduced latency by 30% on the same workloads. Four templates migrated to the new version, and adding OpenAI as a third provider took under a week. Tool calling and structured outputs became consistent across the supported providers.

What changed in my approach

  • Measure the framework's actual limitations before choosing a rewrite.
  • Keep useful abstractions and replace only the parts creating friction.
  • Separate provider integrations from workflow logic.
  • Parallelize only independent work and make merge points explicit.
  • Use latency measurements on equivalent workloads to validate the redesign.
We didn't throw the framework away. We kept what worked and built around what didn't.
